WHY记忆能让 Agent 越跑越好吗

一个所有做 Agent 的人都会问的问题

给 agent 加长期记忆，它会不会「越用越聪明」？这篇用可测量的方式回答，并给出记忆使用的最佳实践。
直觉

记忆 = 自学习

把过去的经验记下来、下次复用，agent 应该会越跑越好。这是几乎所有人的默认假设。

现实

没那么简单

第一版实验「看起来」验证了直觉——但那是一个评分 bug 制造的假象。修正后增益消失。

真相

缺了一个前提

记忆能不能变好，取决于你往里存什么；而能存什么好东西，取决于回路里有没有 oracle。

本文主线：记忆机制是好的——把累积经验注入下一次运行确实生效；但让模型对着自己的产出空想、蒸馏成「经验规则」，产出的是垃圾，甚至帮倒忙。一旦存进 oracle 质量的反馈，同一套机制立刻兑现巨大增益。

PITFALL第一版结果骗了我们

覆盖率「越跑越高」——其实是假象

第一轮带记忆的模式覆盖率 0.82→0.87，像教科书自学习曲线。幸好多问了一句：这把尺子准吗？
问题一 · 评分 bug

裁判会重复计分

分块打分缺了全局约束，同一个抽取项被重复算去匹配多条 GT，系统性高估覆盖率。

铁证：某次只抽 91 条，却报匹配上 94 条 GT——94 > 91 在一对一对齐下根本不可能。

问题二 · 对比混淆

比的根本不是同一个东西

那个「表现好」的记忆模式偷偷用了另一个更强的抽取器，而且没冷启动。

它冷启动（记忆还是空的）时就已经领先——领先跟记忆无关。

修好评分 + 拉平所有变量 + 冷启动重跑后：记忆的增益消失了，带记忆 ≤ 不带记忆。
教训一：先怀疑自己的尺子——来自没校准度量的乐观结果，比没有结果更危险。

DIAGNOSIS为什么没用

不下「记忆无效」的结论，先做错误分析

把漏抽的 GT 全捞出来分类：约 3/4 是「真召回失败」——根本没抽出来。而这些漏项高度同质。
漏项长什么样

都不是「指标+数值」

  • 「外观颜色及喷涂 LOGO 须与甲方确认」
  • 「真空度测量报告 / 真空度测量要求」
  • 「外部油漆等工序」
  • 「承制单位细化设计…提供全套地脚螺栓」

全是散文式、流程式、待确认类的要求。

根因

schema 让模型「以为不该抽」

抽取 schema 天生面向定量指标。模型看到一句没有数值、只有要求的话，就默认「这不是一条指标」直接跳过。

漏的不是模型能力，是它以为这些不该抽。

教训二：「没效果」往往不是终点，而是一个还没做的错误分析。不做归因，就会把「提示词/任务定义问题」误判成「方法无效」。
recall_fail 把「没抽出来」和「抽了对不齐」分开5 / 11

EXPERIMENT · B & C决定性对照

同一记忆机制，只变内容：1/7 vs 7/7

两个实验注入路径完全相同（都是记忆），唯一差别是记忆里存的内容质量。
实验 B · 无 oracle

让记忆「自省」自己的输出

抽完让模型反思自身输出、蒸馏成规则、存进记忆、下轮注入。全程没有标准答案。

跑几轮、沉淀十几条规则后，试金石 钉死在 1 / 7。它只能产出通用文风规则（"复合指标要拆分"），碰不到真问题，还因过度拆分帮倒忙。

实验 C · 有 oracle

把教训当「人类反馈」写进记忆

把实验 A 那条来自错误分析的教训直接写进 AgentCore Memory，用基线提示词跑——教训只从记忆注入。

试金石 7 / 7，覆盖率 0.642 → 0.813，F1=0.813，recall_fail 27→2。目前最好的一次。

因果锁定：记忆的注入机制一直是好的。之前记忆没用，坏的是「无 oracle 自省」产出的内容是垃圾——换成 oracle 质量的反馈，记忆一把兑现全部增益。

BEST PRACTICE记忆使用的最佳实践

怎么用记忆，才能真的越跑越好

记忆负责「捕获并复用」反馈，反馈本身必须由 oracle 提供。落到工程上四条。
01

先确保回路里有 oracle

没有「对错/目标」的外部信号，记忆再多也原地打转。oracle 不必是完整 GT——一次人类纠正、少量标注、带 rubric 的裁判都行。AWS 博客那套 self-learning 有效，正因它吃的是人类/下游反馈。

02

存「具体批评」，别存「抽象规则」

「你漏了真空度测量这一段」有用；「复合指标要拆分」空洞，还诱发过度拆分反噬。记忆要对照答案/原文，指名道姓。

03

oracle 可以只用一次

用少量 GT 做一次错误分析，把结论沉淀成可复用记忆，之后无标注地跑。用少量监督撬动长期收益，最划算。

04

分清想学哪类教训

任务规格类（该抽什么/粒度）必须 oracle；源覆盖/一致性类（漏了原文里的X、重复、格式错）对照原文即可，无 oracle 也能学一点（天花板低）。

TAXONOMY两类教训 · oracle 的形式

什么教训需要 oracle，什么不需要

证据：无 oracle 的自省学不到任务规格（试金石 1/7）；但「对照原文自我批评」无 GT 也救回了 4–10 条漏项。
任务规格类 · 必须 oracle

该抽什么 / 什么粒度 / 什么算一条

从「文档 + 自己的输出」推不出来——模型没有信号知道「这句该成为一条记录」。必须外部权威告诉它。

源覆盖 / 一致性类 · 无 oracle 也能学

漏了原文里的X / 重复了 / 格式错了

对照原文即可发现，不需要标准答案。天花板较低（救回一部分，非全部）。

oracle 的形式它告诉 agent 什么本项目
标准答案 (Ground Truth)这篇「应该」抽出哪些✅ 本文用的
人类反馈「这类也要抽」/「这条错了」博客 self-learning 的真实来源
带评分标准的裁判按 rubric 判每条对不对可选
下游验证抽出的参数拿去用、报错→抽错了可选
对应 LangChain「Level-4 爬山循环」——但爬山需要指明上坡方向的 oracle10 / 11
