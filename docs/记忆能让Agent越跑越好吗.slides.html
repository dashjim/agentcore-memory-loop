THE ANSWER先给结论

能，但记忆是「载体」，不是「老师」

记忆机制本身没问题——它把反馈搬到下一次运行。真正决定成败的，是记忆里存的内容质量，而那取决于回路里有没有判定源。

KEY CONCEPT为什么反馈必须来自它

判定源：整条回路的前提

判定源 = 能告诉 agent「对不对 / 该抽什么」的外部权威。核心：它提供的信息，从输入本身推不出来，必须外部给。
判定源形式告诉 agent 什么
标准答案这篇「应该」抽出哪些
人类反馈「这类也要抽」/「这条错了」
大模型对比标准答案/规范按规范判对错、漏了哪类
下游验证参数拿去用报错 → 抽错了

本文步骤②用的就是「大模型对比标准答案」这一种。

为什么非它不可

模型看着「外观颜色须与甲方确认」，光凭"原文+自己的输出"推不出"这句该成为一条记录"——这个信号藏在判定源里，不在输入里。

一句话

记忆不产生新知识，它只搬运。搬运什么，取决于回路里的判定源。

这也解释了 AWS 博客那套 self-learning 为什么有效——它吃的是人类/下游反馈这个判定源，不是模型的自我空想。
标准答案只是其中一种；后三种在真实系统里很常见4 / 12
STEP ①抽什么 · 基线提示词 · 漏了什么

①基线抽取：先看它漏了什么

用只含 schema + 红线的基线提示词跑一遍，暴露问题——这决定了步骤②要产出什么反馈。
基线抽取 system prompt（节选）
你是工业技术文档信息抽取助手。
针对每条技术要求抽一条记录，字段：
 设备主体/设备部件/指标名称/指标特征/原文
红线：① 忠实抽取，绝不臆造；
 ② 输出严格 JSON 数组；
 ③ 不补单位；④ 不因格式跳过。
（内联自审；你看不到标准答案）
跑完发现：整类漏抽（约 3/4 是"真召回失败"）
  • 外观颜色及喷涂 LOGO 须与甲方确认
  • 真空度测量报告 / 真空度测量要求
  • 外部油漆等工序
  • 承制单位细化设计…提供全套地脚螺栓

都不是「指标+数值」，而是离散文字/流程/待确认类。schema 面向定量指标，模型以为这些不该抽。

STEP ②检查器 · 提示词 · 真实反馈

②大模型对比标准答案，产出反馈

让一个检查器读「抽取结果 + 标准答案」，产出可迁移的规则性反馈（不照抄答案）。标准答案只进这一步。
检查器 system prompt（真实原文）
你是抽取质检专家。给你【抽取结果】
和【标准答案】。对比两者，产出可迁移、
指导未来抽取的改进反馈（≤10 条）：
 ① 系统性漏抽的类别/类型；
 ② 粒度问题（过度拆分/该合并）；
 ③ 规则性、可复用的纠正指引。
不要逐条罗列答案——要给出下次能照做的规则。
它真实产出的反馈（节选·已脱敏）
1. 无损检测(RT/PT/UT)整类缺失 → 须
   作为独立条目抽取，勿因"过程要求"忽略
2. 制造/见证要求(合拢/压力试验须

3. 计算/设计文件交付要求漏抽
4. 外观/标识/土建配合(外观颜色须

9. 非定量/程序性要求也须抽

STEP ③写进记忆 · 类型 · 内容

③把反馈写进 AgentCore Memory

这条反馈作为记忆写入、可跨运行复用。用什么记忆、存成什么样，直接决定下一步的效果。
Memory 类型（怎么存）

用 AgentCore 自定义记忆当「事件存储」：create_event 写、list_events 精确即时读（不走 SEMANTIC/EPISODIC 异步策略——要可控、即时、可复现）。

存在固定分区 canon-{actorId}，每次更新追加一版、读取取最新版；注入时逐字拼进 system prompt 的"已积累经验"段。

记忆里存的内容（真实）
【质检反馈·务必逐条应用】
1. 非定量要求也要抽：定性/流程/
   报告/待确认类 → 映射进 指标名称/特征
2. 覆盖易漏类别：真空度测量/无损检测/
   环境/受压/阀门/管口/材料
3. 粒度对齐：默认一原文一记录
对照坏例子：如果让模型自省自己的输出（无判定源），存进去的是"复合指标要拆分"这类通用文风规则——指不出漏了哪类，还诱发过度拆分。好记忆 = 指名道姓的、来自判定源的反馈。

模型只看自己的产出，没有信号告诉它「离散文字类也算数」。产出通用文风规则，碰不到真问题，还因过度拆分帮倒忙。

BEST PRACTICE记忆使用的最佳实践

怎么用记忆，才能真的越跑越好

记忆负责「捕获并复用」反馈，反馈本身必须由判定源提供。落到工程上四条。
01

先确保回路里有判定源

没有"对错/目标"的外部信号，记忆再多也原地打转。判定源不必是完整标准答案——一次人类纠正、少量标注、带 rubric 的裁判都行。

02

存「具体批评」，别存「抽象规则」

"你漏了真空度测量这一段"有用；"复合指标要拆分"空洞，还诱发过度拆分反噬。记忆要对照答案/原文，指名道姓。

03

判定源可以只用一次

用少量标准答案做一次检查、把结论沉淀成可复用记忆，之后无标注地跑。用少量监督撬动长期收益，最划算。

04

分清想学哪类教训

任务规格类（该抽什么/粒度）必须判定源；源覆盖/一致性类对照原文即可，无判定源也能学一点（天花板低）。

LIMITS & TAKEAWAY诚实局限 · 一句话带走

能说什么，不能说什么

结论方向可信，但边界要讲清——这也是「诚实实验」的一部分。
能说
  • 记忆注入机制有效（这条回路证明）
  • 瓶颈是记忆内容质量，取决于判定源
  • 标准答案/人类/大模型反馈都能兑现增益
  • 提示词/schema 是漏抽的真因，改得动
不能说 / 局限
  • 单文档、小样本、高方差(覆盖率 0.55–0.81 跳)→幅度不强断
  • 泛化未测(未做留出文档评估)
  • 裁判未经人工校准；有测量口径背离
  • V1 曾因评分 bug 误判，已修正
记忆能让 agent 越跑越好——但前提是回路里有判定源把「对错/该抽什么」喂进来。
记忆负责捕获并复用反馈；它是好的载体，不是好的老师。
